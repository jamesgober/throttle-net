# throttle-net v1.1.0 — Correct Under Contention, Fair and Cancel-Safe

**A correctness and hardening release. Upgrade from 1.0.0 is strongly recommended.** Under ordinary multi-threaded use, 1.0.0's token buckets admitted 25–180 times their configured rate — the exact overload the crate exists to prevent. 1.1.0 fixes that, fixes every finding of the 2026-10-13 audit, and adds the features an outbound caller needs most: fair, cancel-safe waiting with timeouts on every limiter, retry guardrails, reconciliation with what the provider reports, and a fuller resilience toolkit. Every 1.0 call site compiles unchanged; `cargo semver-checks` confirms a minor release, and the MSRV stays at Rust 1.85.

## Highlights

- **No over-admission under contention.** The bucket engine is better-bucket 1.1, whose state is a single instant that a stale clock reading can only make stricter. Real-clock stress tests from 2 to 16 threads now hold every limiter to its bound.
- **Fair, cancel-safe waits with timeouts that fail fast.** A waiting acquire reserves its units and sleeps exactly until they accrue, so waiters are served in order; a timeout that cannot be met fails at once; dropping the future gives the reservation back.
- **A unique-key flood costs ~0.4 µs per key, not ~1.8 ms, and can never reset a limited key's allowance.**
- **Retry guardrails:** a `Retry-After` cap, a total time budget, and a shared retry budget against retry storms.
- **Provider reconciliation that actually pauses:** an exhausted window holds the limiter until the server's reset, for single throttles, multi-dimensional limiters, and the LLM presets.
- **New building blocks:** a bulkhead, `timeout` / `fallback` / `hedge`, owned permits, `CircuitBreaker::call`, estimate-then-settle for LLM costs, `tower` layers, and a clock that follows tokio's paused time.

## Security

- **Rate-limit bypass under concurrency (TN-001).** better-bucket 1.0 reused a stale clock reading in its compare-and-swap loop, so a thread that lost a race "refilled" the bucket to full. Measured on 1.0.0: `Throttle::per_second(1000)` granted ~77,000 tokens in two seconds with four threads and ~547,000 with sixteen (the legal bound is about 3,000). Every bucket-backed type — `Throttle`, `Hybrid`, `MultiLimiter`, `PerKey`, `Layered`, the presets, and a `Queue` or `CircuitBreaker` over a throttle — inherited it. The floor is now better-bucket 1.1.
- **Per-key CPU denial of service (TN-003).** Each new key past the cap scanned its whole shard under the write lock; an idle TTL made every insert O(n). Eviction is now a bounded CLOCK scan and an incremental TTL sweep.
- **Limit reset through eviction (TN-011).** Idle or capacity eviction could forget a drained key and hand it a fresh allowance. Only keys whose bucket has recovered are evicted now; a shard full of limited keys refuses a new key (it waits) instead of evicting one.
- **Unbounded queue memory (TN-004)** and **unbounded `Retry-After` waits (TN-013)** are bounded.

## Fixed

- A probe cancelled while waiting (for example by `tokio::time::timeout`) no longer wedges a circuit breaker half-open forever (TN-002), and a slow call admitted before a transition no longer settles the state after it (TN-008).
- The adaptive limiter no longer loses concurrent updates (TN-006), collapses on one burst of correlated failures, or stays pinned at its floor after one fast outlier (TN-007).
- Sliding windows under a millisecond, and zero windows, enforce their limit (TN-009); limits near `u32::MAX` no longer overflow (TN-019).
- Capacities above ~4.29M tokens are exact (TN-010, TN-021); very slow rates refill and `peek` agrees with `acquire` (TN-020).
- `Backoff` can no longer panic on an unbounded ceiling (TN-012).
- OpenAI presets meter one combined token budget instead of admitting up to twice it (TN-033).
- Composites refund units on a lost race instead of leaking them (TN-022); large-cost waiters are no longer starved (TN-023).
- Fractional OpenAI reset durations and RFC 3339 offsets parse (TN-018); metrics reach applications on the `metrics` 0.24 facade (TN-015) with an instance label on every series (TN-014).
- The `no_std` core builds on targets without 64-bit atomics such as `thumbv7em`, and the `std`-only feature combination's tests compile (TN-025).

## Added

- **Waiting surface.** `*_timeout` methods on `Throttle`, `SlidingWindowLog`, `Hybrid`, `MultiLimiter`, `PerKey`, `Layered`, `CircuitBreaker`, `AdaptiveLimiter`, and `Bulkhead`. `Limiter::reserve`, `refund`, and `pause_for` (with conservative defaults), so composites reserve and roll back across constituents.
- **`Throttle`.** A builder with an independent `burst` and `initial` fill, `per_minute`, `smooth` (GCRA-style even spacing), `reserve`, `refund`, `drain_to`, and `pause_for` / `resume` / `paused_for`.
- **Retries.** `Retry::max_retry_after` (default 5 minutes), `max_elapsed`, and `RetryBudget` with `run_with_budget`.
- **`MultiLimiter`.** Aliases for combined budgets, a strict mode that refuses unknown names (`ThrottleError::UnknownDimension`), `try_build`, and `settle_costs` to admit an LLM call on its `max_tokens` estimate and settle with real usage.
- **`PerKey`.** A builder (burst, initial fill, eviction, shards, clock), `reserve`, `refund`, `reset`, `remove`, `clear`, and `MAX_SHARDS`.
- **Resilience.** `Bulkhead`; `resilience::{timeout, fallback, hedge}`; `CircuitBreaker::call`, owned permits, `reset`, and a `Limiter` impl; `AdaptiveLimiter` owned permits, `release`, and a `Limiter` impl; `Vegas::with_probe_interval`.
- **Providers.** `Window::apply`, `RateLimitInfo::sync_multi`, and `sync_requests` / `sync_tokens` for any limiter, all pausing until the reported reset when a window is exhausted.
- **Integration and testing.** The opt-in `tower` feature (`ThrottleLayer`, `CircuitBreakerLayer`, `AdaptiveLayer`) and `TokioClock`.
- **Observability.** Instance names on every limiter; denial, timeout, shed, queue-rejection, retry, and retry-budget counters; state gauges set at construction.

## Changed

- Waiting acquires take their units up front (a reservation) and sleep until they accrue, rather than sleeping and retrying.
- Behaviour you may notice: a `Retry-After` beyond five minutes now ends a `Retry` loop with the error (`max_retry_after(Duration::MAX)` restores 1.0); one burst of failures halves an AIMD limit once; a full `PerKey` shard of still-limited keys refuses a new key; the `PerKey` shard count is raised so no shard holds more than 16,384 keys; repeated `MultiLimiter` names in one call are summed; a paused limiter reports `available() == 0`; `RateLimitInfo::sync_*` also pause.
- Dependency floors: better-bucket 1.1, clock-lib 1.1, error-forge 1.0.2, event-listener 5.4.2, metrics 0.24.6, tracing 0.1.40.

## Performance

Criterion means on Windows 11 x86_64, rustc 1.95.0, on a shared development machine; 1.0.0 was measured in the same session.

| Operation | 1.0.0 | 1.1.0 |
|---|---|---|
| `Throttle::try_acquire` | 36.0 ns | 34.5 ns |
| uncontended `try_acquire` (comparison bench) | 34.9 ns | 36.2 ns |
| `PerKey::try_acquire`, 10,000 keys | 100.3 ns | 63.6 ns |
| `PerKey` new key at the default 1M-key cap | ~1.8 ms (audit) | 0.42 µs |
| `PerKey` insert with an idle TTL, nothing expired | ~26 µs, growing (audit) | 0.27 µs |

`governor` 0.10 measured 9.8 ns on the same machine: it is GCRA over one timestamp, while a `Throttle` reads the OS monotonic clock on every call.

## Documentation

The README, API reference, cookbook, and governor guide were rewritten to match the code, and every Rust block in them now runs as a doctest. New recipes cover timeouts, estimate-then-settle, retry budgets, bulkheads, hedging, provider sync, `tower`, and deterministic testing of waiting code.

## Known issues

- `Hybrid` and `MultiLimiter` read the clock once per constituent for the peek and again for the commit (~150 ns for two buckets, ~360 ns for three dimensions); a single-reading path is planned.
- The `tower` layers charge a fixed cost per request; a per-request cost function is planned.
- `SlidingWindowLog` waiters retry rather than reserve, so under sustained contention a large cost can wait behind smaller ones. Use a token bucket where arrival-order fairness matters.

## What's next

A per-request cost layer for `tower`, single-reading composites, a `reqwest-middleware` integration as a companion crate, and serializable limiter configurations.
